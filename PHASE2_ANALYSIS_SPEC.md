# Phase 2 Technical Specification: Reference Dataset Analysis Layer

## 1. Overview & Non-Clinical Scope

Phase 2 introduces a deterministic numerical comparison and evidence retrieval engine coupled with a secure, narrow LLM adapter boundary.

> [!IMPORTANT]
> **Clinical Disclaimer**: Outputs generated by this system are numerical comparisons against engineering dataset templates and reference patterns. They do not constitute medical diagnoses, biomechanical pathology assessments, or clinical recommendations.

## 3. Reference Dataset Schema

Reference datasets reside in `data/reference_datasets/` (e.g., `sample_gait_dataset.json`).

### Dataset Header Schema
| Field | Type | Required | Description |
|---|---|---|---|
| `dataset_id` | string | Yes | Unique dataset identifier (e.g., `"REF-GAIT-V1"`). |
| `name` | string | No | Descriptive title. |
| `version` | string | Yes | Semantic version string. |
| `unit` | string | Yes | Supported unit: `"normalized"` (0.0 to 1.0) or `"raw_adc_12bit"` (0 to 4095). |
| `description` | string | No | Provenance, recording protocol, or baseline description. |
| `disclaimer` | string | No | Non-clinical disclaimer notice. |
| `records` | array | Yes | Array of record objects. |

### Record Schema
| Field | Type | Required | Description |
|---|---|---|---|
| `record_id` | string | Yes | Unique ID within dataset (e.g., `"REC-GS-01"`). Duplicates are rejected. |
| `pattern` | string | Yes | Human-readable pattern name (e.g., `"Heel Strike"`). |
| `description` | string | No | Biomechanical/engineering description. |
| `pressures` | object | Yes | Map of sensor ID to finite numeric value. Keys must be members of the 15 known sensor locations. |

## 4. Deterministic Comparison Method

### Channel Filtering & Assumptions
1. Comparison evaluates only channels present in the incoming sensor snapshot that have `hasSignal === true` and finite numeric values.
2. Incomplete or unmapped channels are explicitly recorded in `unmapped_or_missing_channels` and are **never coerced to zero**.
3. **Threshold Condition**: If fewer than `minComparableChannels` (default: 3) overlapping active channels exist between the snapshot and a reference template, comparison fails safely with `status: "insufficient_data"`. (e.g., single-channel hardware mode cannot establish planar distribution).

### Mathematical Metrics
For a set of mutually active channels $C$:

$$\text{RMSD} = \sqrt{\frac{1}{|C|} \sum_{c \in C} (s_c - r_c)^2}$$

$$\text{Similarity Score} = \max\left(0, 1 - \text{RMSD}\right)$$

Where:
- $s_c$ is the incoming sensor reading on channel $c$ ($0.0 \le s_c \le 1.0$).
- $r_c$ is the reference template reading on channel $c$ ($0.0 \le r_c \le 1.0$).
- Residual channel delta: $\Delta_c = s_c - r_c$.

### Deterministic Tie-Breaking
When two records have identical similarity scores:
1. Primary sort: `similarity_score` descending.
2. Secondary sort: `rmsd_distance` ascending.
3. Final deterministic tie-breaker: `record_id` ascending lexicographically (`a.record_id.localeCompare(b.record_id)`).

## 5. LLM Adapter Security Boundary & Output Schema

### Security Rules
- **Zero Frontend Credentials**: No API keys or authorization headers exist in frontend code, test fixtures, client payloads, or logs.
- **Server Environment Read Only**: In server environments (Phase 4), credentials are read from `process.env.GEMINI_API_KEY` or `process.env.LLM_API_KEY`.
- **Offline Test Fake**: `TestMockLLMAdapter` provides offline unit testing without external network requests or keys.

### Strict Output Schema Validation
The model output is treated as untrusted input. The validator enforces:
1. `cited_record_ids` **must be a strict subset** of the deterministically matched record IDs. Any fabricated or uncited IDs are immediately rejected.
2. If the model fails or returns non-conforming data, `generateDeterministicFallback()` generates a structured response derived directly from the numerical comparison evidence.

## 6. How Phase 4 Will Connect

In Phase 4 (backend integration):
1. A FastAPI endpoint (e.g., `POST /api/analyze`) will receive session frames.
2. It will instantiate `AnalysisEngine` with the active reference dataset.
3. The server will supply `process.env.GEMINI_API_KEY` to the adapter.
4. The frontend will consume the validated structured payload.
